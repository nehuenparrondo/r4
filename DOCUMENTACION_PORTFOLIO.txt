PORTFOLIO PERSONAL R4 — PARRONDO NEHUEN
DOCUMENTACIÓN TÉCNICA Y GUÍA DE FUNCIONAMIENTO

1. OBJETIVO DEL PROYECTO

El proyecto es un portfolio personal single-page desarrollado con React y TypeScript. Su objetivo es presentar el perfil, la formación, las habilidades, los logros, la experiencia laboral, los proyectos y los datos de contacto de PARRONDO Nehuen.

Además de la vista pública, incluye un panel privado que permite administrar el contenido mediante operaciones de alta, baja y modificación. En producción, los datos se guardan en PostgreSQL a través de Supabase. El nombre PARRONDO Nehuen está protegido y no aparece como campo editable.

2. TECNOLOGÍAS PRINCIPALES

- Vite: prepara el entorno de desarrollo y genera la versión optimizada de producción.
- React: construye la interfaz mediante componentes funcionales.
- TypeScript: tipa componentes, propiedades, eventos, formularios, datos, contexto, servicios y pruebas. Los componentes utilizan la extensión .tsx y la lógica utiliza .ts.
- Framer Motion: controla las animaciones de entrada y las interacciones visuales.
- Supabase: expone la base PostgreSQL y las funciones RPC utilizadas por el panel administrativo.
- DOMPurify: elimina contenido HTML no permitido antes de guardar datos.
- Lucide React: aporta los íconos de la interfaz.
- Vitest: ejecuta las pruebas automáticas.
- ESLint: revisa la calidad y consistencia del código.

3. ORGANIZACIÓN GENERAL

La aplicación se divide en componentes públicos, componentes administrativos, contextos, hooks, servicios, datos iniciales, utilidades y estilos.

src/components:
Contiene Header, Hero, About, Skills, Experience, Projects, Contact, Footer y FloatingControls. Cada componente representa una sección o control visible.

src/components/admin:
Contiene el panel privado, los formularios reutilizables, la configuración de entidades y la confirmación integrada para eliminar registros. No se utilizan alert, confirm ni prompt nativos del navegador.

src/context:
Incluye ThemeProvider y PortfolioProvider. Estos providers comparten el tema y los datos con toda la aplicación.

src/hooks:
Incluye hooks propios para el tema, los datos, el controlador ABM, el seguimiento de secciones, las acciones de contacto y otras conductas reutilizables.

src/services:
Contiene la conexión con Supabase y el servicio que decide si trabaja con PostgreSQL o con almacenamiento local.

src/data:
Contiene el nombre protegido y los datos iniciales que se usan en el modo local.

src/utils:
Contiene la sanitización y las validaciones de formularios.

src/types:
Contiene los contratos TypeScript compartidos para habilidades, experiencias, proyectos, logros, contacto, entidades administrables y contexto global.

supabase/migrations:
Contiene el esquema relacional, las políticas de seguridad, las funciones administrativas y las cargas de datos versionadas.

4. FUNCIONAMIENTO DE LA PÁGINA PÚBLICA

Header:
Muestra la identidad NP, la navegación entre secciones y el botón Administrar. En pantallas pequeñas, la navegación se convierte en un menú desplegable.

Hero:
Presenta el nombre protegido, el perfil técnico y los accesos de contacto. En una computadora, los botones de email y teléfono copian el dato al portapapeles y muestran una confirmación dentro de la página. En un celular, conservan el comportamiento nativo de correo y llamada.

Sobre mí:
Describe el perfil, la formación secundaria y primaria, utilizando únicamente los datos aportados por el propietario.

Habilidades y logros:
Las habilidades se muestran como tarjetas. Los logros se presentan uno debajo de otro en una lista visual. Ambos grupos se leen desde la base de datos o desde el modo local.

Experiencia:
Presenta los trabajos y actividades en tarjetas adaptables. Cada registro incluye puesto, empresa o ámbito, descripción y período cuando está disponible.

Proyectos:
Cada proyecto usa el mismo formato: número visual, nombre, descripción, tecnologías y enlaces. Los proyectos cargados son el Portfolio R4, APIs — Fetch, Axios, BBDD — JS5 y Express y DHTML — NJS3.

Contacto:
Permite copiar email y teléfono en computadoras. En celulares abre la aplicación correspondiente. WhatsApp utiliza una URL web compatible con computadoras y dispositivos móviles.

Controles flotantes:
El botón de tema permanece en la esquina inferior derecha. Cambia entre modo oscuro y claro y guarda la preferencia en localStorage. El botón para volver arriba aparece únicamente cuando la página tiene suficiente altura y el usuario se desplazó hacia abajo.

5. PANEL ADMINISTRATIVO Y ABM

El botón Administrar abre un panel lateral protegido por clave. La clave no se guarda en el código ni en las variables públicas. PostgreSQL conserva únicamente un hash bcrypt dentro de un esquema privado.

Las entidades administrables son:
- Habilidades.
- Experiencias.
- Proyectos y sus tecnologías.
- Logros.
- Datos de contacto.

Alta:
El usuario abre un formulario, completa los campos y guarda. La interfaz valida y sanitiza los datos antes de enviarlos.

Modificación:
El botón de edición carga los datos actuales en el mismo formulario reutilizable.

Baja:
El botón de eliminación abre una confirmación diseñada dentro de React. Solo al confirmar se ejecuta la eliminación. No se usan cuadros de diálogo nativos.

6. PERSISTENCIA Y BASE DE DATOS

La base usa tablas separadas para skills, experiences, projects, technologies, project_technologies, achievements y contact. Las tecnologías están normalizadas en un catálogo y se vinculan con proyectos mediante una tabla muchos-a-muchos.

Las lecturas públicas utilizan solicitudes GET porque no contienen claves ni datos privados. La verificación de acceso y todas las escrituras usan funciones RPC mediante POST, enviando los parámetros dentro del cuerpo HTTPS.

Row Level Security permite leer el contenido público y bloquea escrituras directas. Las altas, modificaciones y bajas se realizan exclusivamente mediante funciones SECURITY DEFINER que verifican la clave administrativa y aceptan una lista cerrada de entidades.

7. MODO LOCAL

Si VITE_SUPABASE_URL o VITE_SUPABASE_ANON_KEY no están configuradas, el portfolio activa un modo de demostración. En ese modo, los datos y el hash SHA-256 de una clave local se guardan en localStorage. Este mecanismo permite evaluar el ABM sin conectarse a Internet, pero la producción utiliza PostgreSQL.

8. TEMA Y DISEÑO RESPONSIVE

El tema se guarda en localStorage bajo la clave portfolio-theme. Al iniciar, la aplicación recupera la preferencia guardada o utiliza la configuración del sistema.

El diseño oscuro combina fondos casi negros con acentos rosas. El tema claro conserva la misma identidad con fondos claros y rosas más profundos. Las grillas cambian automáticamente según el ancho disponible para mantener una correcta lectura en escritorio, tablet y celular.

9. SEGURIDAD

- La clave administrativa no forma parte del repositorio.
- La clave se compara contra un hash bcrypt privado.
- RLS bloquea escrituras públicas directas.
- Las RPC administrativas usan POST.
- DOMPurify elimina HTML no permitido.
- React escapa el texto al renderizar.
- Las URLs se validan para aceptar únicamente HTTP o HTTPS.
- Los formularios limitan longitudes y campos obligatorios.
- La eliminación requiere una confirmación interna.
- El archivo .env está excluido de Git.

10. COMANDOS DE DESARROLLO

Instala las dependencias.

npm run dev
Inicia el servidor local de Vite.

npm run test
Ejecuta las pruebas con Vitest.

npm run lint
Revisa el código con ESLint.

npm run typecheck
Comprueba el tipado estricto con el compilador de TypeScript sin generar archivos.

npm run build
Ejecuta primero el control de TypeScript y luego genera la carpeta dist lista para producción.

npm run preview
Permite revisar localmente la compilación de producción.

11. VARIABLES DE ENTORNO

VITE_SUPABASE_URL:
Dirección pública del proyecto Supabase.

VITE_SUPABASE_ANON_KEY:
Clave pública utilizada por el cliente. RLS impide que esta clave realice escrituras directas.

VITE_PUBLIC_SITE_URL:
Dirección pública final del portfolio.

Los valores reales se guardan en .env, archivo que no se incluye en Git ni en el entregable.

13. DATOS QUE NO SE INVENTARON

Los repositorios académicos agregados no incluyen README ni descripción pública. Por ese motivo, sus descripciones se limitan a los temas explícitos presentes en los nombres de los repositorios. No se agregaron fechas, instituciones, enlaces de demostración, fotografías ni datos personales no proporcionados.

14. ENTREGA

El archivo ZIP de entrega excluye .git, node_modules, el archivo .env y carpetas temporales. Incluye el código fuente TypeScript/TSX, tsconfig.json, package-lock.json, README, esta documentación, las migraciones SQL, los recursos públicos y la compilación dist. No contiene archivos JSX.

15. MAPA DETALLADO DE ARCHIVOS IMPORTANTES

index.html:
Documento HTML base. Define idioma, metadatos, favicon, el elemento root y la carga de src/main.tsx.

src/main.tsx:
Punto de entrada de React. Comprueba que exista el nodo root, crea la raíz de React, activa StrictMode y envuelve App con ThemeProvider y PortfolioProvider.

src/App.tsx:
Compone la única página. Ordena Header, Hero, About, Skills, Experience, Projects, Contact, Footer, controles flotantes y panel administrativo. También presenta los estados globales de carga y error.

src/types/portfolio.ts:
Fuente central de tipos. Declara entidades, datos de contacto, estructura completa del portfolio, valores de formularios y contrato del contexto. Evita duplicar tipos y permite que TypeScript detecte incompatibilidades.

src/data/portfolioSeed.ts:
Contiene el nombre protegido y los datos iniciales reales. Se utiliza como respaldo visual inmediato y como base del modo local.

src/context/ThemeContext.ts y ThemeProvider.tsx:
Definen el contrato del tema y mantienen la preferencia claro/oscuro. El provider actualiza el atributo data-theme del documento y localStorage.

src/context/PortfolioContext.ts y PortfolioProvider.tsx:
Definen y publican el estado compartido del portfolio. Permiten que cualquier sección consulte datos o ejecute acciones ABM sin pasar propiedades por muchos niveles.

src/hooks/useTheme.ts:
Valida que ThemeContext esté disponible y devuelve el tema actual y toggleTheme.

src/hooks/usePortfolioData.ts:
Valida que PortfolioContext esté disponible y devuelve datos, carga, errores y operaciones persistentes.

src/hooks/usePortfolioController.ts:
Coordina la carga inicial, refresh, altas, modificaciones y bajas. Después de cada escritura vuelve a consultar la fuente para mantener toda la interfaz sincronizada.

src/hooks/useScrollSpy.ts:
Usa IntersectionObserver para detectar la sección principal visible y actualizar el enlace activo del menú.

src/hooks/useContactActions.ts:
Detecta computadoras y celulares. En computadora copia email o teléfono con Clipboard API y muestra feedback; en celular permite mailto y tel nativos.

src/services/supabaseClient.ts:
Lee las variables VITE_SUPABASE_URL y VITE_SUPABASE_ANON_KEY. Crea el cliente público solo cuando están disponibles y desactiva sesiones de autenticación innecesarias.

src/services/portfolioService.ts:
Capa principal de persistencia. Selecciona automáticamente Supabase o localStorage. Lee datos, transforma la relación de tecnologías, verifica acceso, envía RPC por POST y ejecuta ABM local o remoto.

src/utils/sanitize.ts:
Elimina HTML no permitido con DOMPurify y sanitiza todos los textos o listas de un formulario.

src/utils/validation.ts:
Aplica límites, campos obligatorios, formato de email y teléfono, tecnologías mínimas y protocolos permitidos para URLs. Devuelve valores normalizados, errores por campo y estado de validez.

src/components/Header.tsx:
Controla navegación fija, indicador de sección, menú responsive y apertura del panel administrativo.

src/components/FloatingControls.tsx:
Mantiene el selector de tema flotante y calcula cuándo debe aparecer el botón para volver arriba.

src/components/Section.tsx:
Componente reutilizable para títulos y animaciones de entrada de todas las secciones públicas.

src/components/admin/AdminPanel.tsx:
Gestiona apertura, autenticación, cierre de sesión local y selección de la entidad que se quiere administrar.

src/components/admin/EntityManager.tsx:
Lista registros y coordina agregar, modificar y solicitar la eliminación de habilidades, experiencias, proyectos y logros.

src/components/admin/EntityForm.tsx:
Genera formularios desde entityConfig, prepara valores, convierte tecnologías separadas por comas, valida y guarda.

src/components/admin/DeleteConfirmation.tsx:
Implementa la confirmación de baja dentro de React. Reemplaza confirm y alert del navegador y controla estados de progreso y error.

src/components/admin/ContactForm.tsx:
Modifica email y teléfono. El nombre PARRONDO Nehuen no forma parte de sus valores y permanece protegido.

src/components/admin/entityConfig.ts:
Describe los campos, etiquetas, tipos y nombres de cada entidad. Permite reutilizar EntityForm y EntityManager.

supabase/migrations/202609200001_initial_portfolio.sql:
Crea tablas normalizadas, restricciones, índices, RLS, funciones RPC, datos iniciales y esquema privado para el hash administrativo.

supabase/migrations/202609200002_publish_urls.sql:
Actualiza los enlaces públicos del repositorio y el despliegue.

supabase/migrations/202609210001_projects_achievements.sql:
Agrega de forma idempotente los dos proyectos académicos adicionales, sus tecnologías y los tres logros.

vite.config.ts:
Configura React, Vitest, exclusiones de pruebas y división de paquetes para optimizar la compilación.

tsconfig.json:
Activa TypeScript estricto, JSX de React, APIs del navegador, resolución moderna de módulos y verificación sin emisión.

eslint.config.ts:
Aplica reglas de JavaScript, TypeScript, hooks y actualización rápida de React. Excluye compilaciones y carpetas temporales.

ABRIR_PORTFOLIO.bat:
Asistente para Windows. Comprueba Node.js, instala dependencias si faltan, genera dist si es necesario y sirve el portfolio en el puerto 4173.

GUIA_PARA_ABRIR_EN_LA_ESCUELA.txt:
Explica métodos de apertura, requisitos, comandos, problemas frecuentes y alternativas cuando la computadora escolar no permite instalaciones.

16. PROCEDIMIENTO RECOMENDADO EN LA ESCUELA

Método principal con Internet:
Abrir https://r4-theta.vercel.app/ para mostrar inmediatamente la versión publicada y conectada con Supabase.

Método desde el pendrive:
1. Copiar el ZIP a la computadora.
2. Extraerlo completamente.
3. Entrar en la carpeta resultante.
4. Ejecutar ABRIR_PORTFOLIO.bat.
5. Esperar la instalación inicial de dependencias.
6. Mostrar el sitio en http://127.0.0.1:4173.
7. Mantener abierta la consola mientras se utiliza el sitio.

Método para explicar el código:
Abrir la carpeta extraída en Visual Studio Code. Mostrar src/App.tsx como composición general, src/types/portfolio.ts como modelo TypeScript, src/services/portfolioService.ts como persistencia, src/components/admin como ABM y supabase/migrations como capa SQL.

Limitación externa:
Para instalar dependencias en una computadora nueva se necesita Node.js y acceso a npm. Si la institución bloquea instalaciones o Internet, debe usarse la URL de Vercel. Nunca se debe copiar una contraseña administrativa dentro del ZIP.
